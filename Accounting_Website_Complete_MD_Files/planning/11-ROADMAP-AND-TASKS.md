# Roadmap and Implementation Tasks

## Phase 0 — Discovery / approvals
- [ ] Confirm firm name, brand/domain and business jurisdiction.
- [ ] Confirm each service actually sold; remove unapproved offerings.
- [ ] Determine booking provider and CRM/email destination.
- [ ] Agree contact fields, legal pages, language and pricing approach.
- [ ] Approve sitemap, visual direction and success metrics.

## Phase 1 — UX and UI
- [ ] Desktop/mobile homepage wireframes.
- [ ] Design system tokens, components, responsive patterns.
- [ ] Service listing and service detail page template.
- [ ] Payroll landing page with scoped copy and enquiry form.
- [ ] About/contact/industry/legal templates.
- [ ] Form error, loading and confirmation states.

## Phase 2 — Frontend and CMS
- [ ] Set up repository, environments, CI checks.
- [ ] Build layout, nav, footer, buttons and components.
- [ ] Implement all P0 pages and CMS models.
- [ ] Integrate forms, lead destination and notifications.
- [ ] Integrate booking flow and fallback contact option.
- [ ] Add technical SEO, analytics events and legal links.

## Phase 3 — QA/security/content
- [ ] Review copy and service/regulatory claims.
- [ ] Verify authenticated CMS permissions and backup plan.
- [ ] Test lead delivery and failure/retry cases.
- [ ] Mobile/responsive, keyboard/screen-reader QA.
- [ ] Check page performance on real or throttled mobile.
- [ ] Verify consent/cookie handling and privacy links.

## Phase 4 — Launch
- [ ] Deploy production and configure HTTPS + redirects.
- [ ] Verify production email, forms and scheduling.
- [ ] Submit sitemap and set up search console.
- [ ] Enable error monitoring and lead-delivery alarms.
- [ ] Capture post-launch baseline KPI metrics.

## Phase 5 — Post-MVP
- [ ] Articles/resources.
- [ ] Verified case studies and testimonials.
- [ ] Industry landing pages and iterative conversion testing.
- [ ] Secure client portal discovery only if separately approved.

## Definition of Done
A task is done when developed, reviewed, tested in responsive states, accessible for its use case, documented and accepted by the owner. Do not substitute styled mock data for functioning enquiry/booking integration.
